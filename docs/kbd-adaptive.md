# 屏幕自适应几何规则（定稿）

状态：2026-11-11 1.1。webdemo 为真值来源，Android 按本文移植。

## 1. 输入

| 输入 | 含义 |
|---|---|
| W, H | IME 可用窗口像素，不是系统方向 |
| b | 竖屏底部安全区，默认取系统 inset；`\sb=num` 覆盖，`\sb=auto` 恢复自动 |
| R | 屏幕 W/H 阈值，固定 0.75 |

模式是输出，不再读取 `Configuration.orientation`。

```
竖屏可行：W ≥ 160 且 H ≥ 208 + b
横屏可行：W ≥ 256 且 H ≥ 144

只有一个可行 → 选它
两个都可行：
    W/H > 0.75  → 横屏
    W/H ≤ 0.75  → 竖屏
```

R=0.75 的含义：3:4（W/H=0.75）走竖屏，4:5（0.8）及更宽走横屏。常见 16:9 / 18:9 / 20:9 手机仍走竖屏。

## 2. 变量

```
n   字体级，f = 16n
K   键宽，K = 16 + 2t（偶数）
g   8 条普通缝
c   中缝，c = g 或 g+1
m   左右外边距（单侧）
b   竖屏底部安全区
e   c − g ∈ {0,1}
```

键盘宽高比检查区间（仅提示，不硬切换）：

```
竖屏键盘比 [1.0, 1.6]
横屏键盘比 [1.7, 5.0]
```

## 3. 竖屏

```
W = 2m + 10K + 8g + c
  = 160 + 2m + 9g + 20t + e
空格宽 = 2K + c
键高 h = 3f + 2g = 48n + 2g
键盘高 Hk = 13f + 12g + b = 208n + 12g + b
```

### 3.1 宽度进位

上限沿用 720 设计：

```
m_max = n
g_max = c_max = 2n
K_max = 34n    →  t_max = 17n − 8
```

级起点：

```
n = 1：t=0，g=c=0，m=0
n ≥ 2：t=17(n−1)−8，g=c=2(n−1)，m=n−1
```

给定 W，在级内：

1. 先取能放下 W 的最大 g（受高度限制时取 `floor((H−b−208n)/12)`）；
2. 再取能放下 W 的最大 t；
3. 余量交给 m，奇偶交给 e：

```
e = (W − 160 − 9g − 20t) & 1
m = (W − 160 − 9g − 20t − e) / 2
c = g + e
```

m 是低位缓冲，进位前允许超过名义上限（约 0–4px；t 进位时约 0–9px），进位瞬间回落。固定屏幕上看到的只是一个侧边距，不会动画。

### 3.2 高度与字体级

竖屏字体级先由宽度级决定：

```
n_w = max(1, ceil(W / 360))
```

再用高度向下压：

```
H ≥ 208n + 12·g_start(n) + b
g_start(1)=0，g_start(n≥2)=2(n−1)
```

H 不够时 n 不升，K 可以超过 `34n` 继续变宽；此时读数标记 `k 超本级上限`。

### 3.3 级落点（不含额外 m 呼吸）

| n | f | K | g | m | W | Hk（b=32） |
|---|---:|---:|---:|---:|---:|---:|
| 1 起 | 16 | 16 | 0 | 0 | 160 | 240 |
| 1 顶 | 16 | 34 | 2 | 1 | 360 | 232 |
| 2 起 | 32 | 34 | 2 | 1 | 360 | 472 |
| 2 顶 | 32 | 68 | 4 | 2 | 720 | 496 |
| 3 起 | 48 | 68 | 4 | 2 | 720 | 704 |
| 3 顶 | 48 | 102 | 6 | 3 | 1080 | 728 |
| 4 起 | 64 | 102 | 6 | 3 | 1080 | 936 |
| 4 顶 | 64 | 136 | 8 | 4 | 1440 | 960 |

## 4. 横屏

```
w_K   = 2K + g
w_Ks  = p·K + (p−1)g + e      (p ≥ 2)
W     = 2w_K + 10K + w_Ks + 12g + 2m
      = (14+p)K + (p+13)g + e + 2m
W_min = 16K
Hk    = 9f + 8g = 144n + 8g
```

- 字体级复用竖屏短边级，再被横屏宽高压制：
  `n_short = max(1, ceil(min(W,H)/360))`，再降到满足 `W ≥ 16K_start(n)` 和 `H ≥ 144n + 8g_start(n)`。
- `K` 先到本级上限，`p` 在 2..6 之间取能放下的最大值，余量给 `m`。
- `w_K = 2K+g`，所以 720 横屏外列宽 140，与竖屏空格 `2K+c`（c=g=4）一致。
- 横屏没有 `b`；底部安全区由系统窗口处理。

720 横屏验算：`p=6,K=68,g=4,m=84` →
`20×68 + 19×4 + 2×84 = 1604`，`H=320`。

## 5. 候选

候选几何使用当前布局的 `S=f`、`g`、`K`：

```
格宽 = keys·K + (keys−1)·g
最小 2 键宽，偶数倍键宽，不缩写
超长按行宽折行，不截断
行高 = slots·f + (slots−1)·g
```

- 竖屏行宽 10 键；展开面板高 `mainH`。
- 横屏行宽 `p` 键；收起面板高 `2·keyH+g`，展开面板高 `kbH`。
- 常驻候选行是序列第 0 行。

## 6. 修饰键标签

```
Ctrl / Alt / Shft
Ct   / Al  / Sh
```

统一紧凑开关：修饰键取最长标签 `Ctrl/Shft = 2f`，若 `2f ≥ 键宽 − 2`，或 `Tab/Esc` 放不下，则 `Ct/Al/Sh` 与 `Ta/Es` 同时生效；否则全部全称。这样不会出现 `Ct/Al/Sh` 与 `Tab/Esc` 混排。

已验证：

| 尺寸 | 键宽 | f | 标签 |
|---|---:|---:|---|
| 720×1604 竖 | 68 | 32 | Ctrl / Alt / Shft |
| 768×1024 竖 | 70 | 48 | Ct / Al / Sh |
| 300×260 横 | 34 | 16 | Ct / Al / Sh |
| 800×800 横 | 96 | 32 | Ct / Al / Sh + Ta / Es |
| 1024×768 横 | 124 | 32 | Ctrl / Alt / Shft |
| 1604×720 横 | 140 | 32 | Ctrl / Alt / Shft |

`800×800` 的修饰键本身放得下，但字母键上的 `Tab/Esc` 放不下，所以整体进入紧凑模式；`1024×768` 两者都放得下，保持全称。

## 7. b 与 `\sb` 命令

- 默认 `b` 取系统底部 inset（navigationBars | systemGestures）。
- `\sb=32`：覆盖为 32px。
- `\sb=auto`：恢复系统值。
- 覆盖值持久化到 `SharedPreferences("kbd")` 的 `bottomSafe`，-1 表示自动。
- `b` 只参与竖屏；横屏忽略。

## 9. Android 移植映射

| webdemo | Android |
|---|---|
| `layout.js compute()` | `KbdLayout(W,H,b)` |
| `orientation` | `KbdLayout.landscape` |
| 动态 `S/g/K` | `KbdLayout.S/g/k`，渲染不再用 `scale` |
| 候选装箱 | `KbdLayout` 实例方法 |
| 符号列数 | `KbdLayout.symbolCols` |
| 修饰键/副标签短标签 | `KbdRenderer.compactLabels` 统一判断 |
| `R / h_a / b` 控制 | `\sb` 命令 + 系统 inset；R 固定 0.75 |

## 10. 移植状态与待定项

已确认：

- 横屏 `p=2` 是正常现象，Android 候选有跨行机制兜底；webdemo 的候选强制截断只是简化，不作为真值。
- `Tab → Ta`、`Esc → Es` 与 `Ct/Al/Sh` 统一开关（见第 6 节）；Shift+Tab / Shift+Esc 已支持。
